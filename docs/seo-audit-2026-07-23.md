# SulitScan SEO Audit — July 23 Growth Release

Date documented: 2026-07-24  
Release baseline: `b980b1c`  
Audited release head before documentation: `603cd43`

## Executive summary

This release closes three confirmed crawl and sharing gaps: inactive deal records could still resolve
as public detail pages, category/store pages exposed only their first 24 items in server HTML, and
entity sharing metadata was incomplete. It also publishes five evidence-led guides and a
browser-only final-checkout comparison tool that does not claim live prices, coupons, or a
guaranteed lowest price.

The repository work does **not** fix the current temporary `www.sulitscan.com` redirect because the
Vercel domain redirect runs before application middleware. That remains a deployment-owner action.
The PageSpeed API returned HTTP 429 during the release audit, so this report intentionally contains
no current lab score or Core Web Vitals claim.

## Confirmed findings and release disposition

### 1. Inactive and demo deal routes were publicly resolvable

**Before:** hidden demo/inactive records, including the old SHEIN demo, could be resolved directly
by slug even though they were omitted from normal active-deal lists. That made stale detail routes
indexable and clickable outside the intended public catalog.

**Implemented:** public slug lookup now applies the same centralized public-deal eligibility rule as
the rest of the catalog. Ineligible records resolve through the route's not-found path. Regression
coverage confirms these representative URLs return a real 404 and carry `noindex`:

- `https://sulitscan.com/deals/summer-dress-shein`
- `https://sulitscan.com/deals/xiaomi-smart-band-9-shopee`

The compliance test also asserts that both slugs are absent from public lookup and that the blocked
SHEIN creative is not published as a public asset.

**Impact:** removes thin, outdated commercial pages and keeps public discovery aligned with active
affiliate inventory.

### 2. Category and store depth was not crawlable beyond the first 24 items

**Before:** category and store pages server-rendered the first 24 deals, then exposed deeper items
through a client-only load-more interaction. Deeper results had no stable URL for search discovery
or sharing.

**Implemented:** both entity types now use server-rendered 24-item URL pagination. Page 2+ has a
self-referencing canonical, page-aware Open Graph/Twitter URL, correctly offset ItemList positions,
and crawlable previous/next page links. Invalid page values are normalized and marked `noindex`.
The sitemap now emits every valid unfiltered entity page and never emits `?page=1`.

### 3. Deal, category, and store sharing metadata was incomplete

**Before:** entity pages did not consistently provide page-specific Open Graph and Twitter fields.

**Implemented:** active deal, category, and store routes now generate entity-specific titles,
descriptions, canonical URLs, Open Graph URLs/images, and Twitter card metadata. Paginated category
and store metadata includes the normalized page number. Inactive deal routes do not receive an
indexable entity preview because they now return 404.

### 4. A useful commercial utility was missing

The release adds `https://sulitscan.com/tools/checkout-comparison`, a user-entered calculator for
comparing final checkout totals and per-unit costs. Inputs remain in the browser; analytics contains
only fixed source attribution. The page explicitly says it does not monitor live store prices,
verify coupons, or guarantee the lowest price. This is the deliberate response to competitor
patterns documented in the competitor summary: provide a trustworthy decision tool without
pretending SulitScan has live pricing or coupon feeds.

### 5. `www` still redirects temporarily to the apex domain

**Confirmed external state:** `https://www.sulitscan.com/` returns a temporary redirect to the apex
host even though repository middleware intends permanent canonicalization.

**Required external action:** in the Vercel project domain settings, change the `www.sulitscan.com`
redirect to a permanent 301 or 308 targeting `https://sulitscan.com`. After deployment, verify both
the homepage and at least one deep path with an HTTP header check. Do not mark this fixed based on the
repository release alone.

### 6. No current PageSpeed score is available

The PageSpeed API request was rate-limited with HTTP 429. No current lab score is published in this
audit. Re-run PageSpeed Insights after deployment when the API is available, then record the test
URL, device mode, timestamp, and actual result without extrapolating from repository checks.
