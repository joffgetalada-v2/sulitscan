# SulitScan Full SEO Audit

Date: 2026-07-19  
Scope: live production site and repository  
Live pages crawled: 212 public URLs through Firecrawl, plus targeted HTTP and rendered-metadata checks

## Executive summary

SulitScan has no critical crawl or indexation blocker. The sitemap, robots rules, canonical URLs, HTTPS behavior, headings, structured data, internal links, disclosures, and image alternative text are broadly healthy. The next growth release should not be a content-only sprint: the strongest confirmed opportunity is to reduce the listing page's client payload and make deeper deal results crawlable through URL-based pagination, while correcting several smaller metadata and structured-data gaps.

The site also has enough active inventory to support five new, non-overlapping commercial guides. New content should focus on student essentials, cookware decisions, bags, carry-on luggage, and makeup brushes. These topics map to current products and avoid duplicating the existing Temu, Shopee-safety, import-tax, home-organization, beauty-under-500, phone-accessory, work-from-home, and gift guides.

## Confirmed strengths

- `robots.txt` allows public pages, blocks API routes, and references `https://sulitscan.com/sitemap.xml`.
- The live sitemap contains canonical, indexable URLs and no retired Shopee article URL.
- All sitemap pages sampled by the audit return HTTP 200 and use self-referencing canonicals.
- Nonexistent routes return a real 404; the retired Shopee guide returns a permanent redirect.
- Every crawled HTML page has a title, description, and one H1. No duplicate titles were found.
- Rendered JSON-LD parses successfully and includes the appropriate Organization, WebSite, BreadcrumbList, ItemList, BlogPosting, and FAQPage types where used.
- Image alternative text, affiliate disclosures, external-link attributes, skip navigation, and mobile-menu labels are consistently present.
- The repository baseline passes lint, TypeScript, recommendation tests, link and affiliate guards, product-quality checks, and the 219-page production build.

## Findings and action plan

### High: listing payload and uncrawlable deeper results

**Evidence:** `/deals` sends all active deal data to a client component, renders the first 24 cards, and requires repeated client-only `Load more` actions for the remaining products. The live HTML is approximately 372 KB and first-load documents reference roughly 1 MB of JavaScript. Store and category listings use the same pattern.

**Impact:** heavier mobile parsing/hydration can hurt responsiveness and conversion, while products beyond the first client-rendered set lack stable, shareable discovery URLs.

**Fix in this release:** convert `/deals` to server-filtered, URL-based pagination, render only one page of cards, preserve search/filter/sort as GET parameters, provide crawlable page links, noindex arbitrary filtered searches, self-canonicalize unfiltered pagination pages, remove Framer Motion from deal cards, and prioritize the first visible card images.

### Medium: article sharing metadata and update schema

**Evidence:** article Open Graph data is article-specific, but Twitter/X metadata inherits the homepage title, description, and image. BlogPosting JSON-LD includes `datePublished` but not the visible `lastReviewed` value as `dateModified`.

**Impact:** weaker social preview relevance and incomplete freshness signals.

**Fix:** generate article-specific Twitter cards and add accurate `dateModified` plus an author/editorial-policy URL to BlogPosting JSON-LD.

### Medium: deal search snippets are long and occasionally duplicated

**Evidence:** most deal titles exceed common search-display lengths because the complete product title is followed by platform and site suffixes. Six duplicate-description groups affect thirteen live deal URLs because generic buyer notes are truncated before product-specific text appears.

**Impact:** search engines may rewrite snippets, and near-identical descriptions give users less reason to choose a result.

**Fix:** add deterministic metadata helpers that preserve the distinguishing product phrase, platform, and brand within practical limits; begin every description with product-specific language.

### Medium: one unfinished category is indexable

**Evidence:** `/categories/digital-tools` returns HTTP 200, `index, follow`, and a self-canonical despite showing zero deals and “Coming soon.” It is absent from navigation and the sitemap.

**Impact:** a thin, orphaned page can be discovered outside the intended architecture and contributes no useful search value.

**Fix:** return `noindex, follow` until the category has substantive inventory and content.

### Medium: content evidence and authorship can be clearer

**Evidence:** the editorial policy explains SulitScan's process, but individual guides use a generic team byline and rarely include a visible, article-specific assessment note or primary source beside time-sensitive claims.

**Impact:** readers and search systems have less page-level evidence for why a guide deserves trust.

**Fix:** every new guide includes a visible “How we assessed this guide” section, current primary-source links for dynamic rules, a review date, clear non-testing language, and a link to the editorial policy. Do not invent a named expert or claim physical testing.

### Medium: `www` hostname uses a temporary redirect

**Evidence:** `https://www.sulitscan.com/` returns HTTP 307 to the apex domain even though repository middleware intends a permanent redirect. Vercel's domain-level redirect runs before application middleware.

**Impact:** weaker hostname-consolidation signal than a 301/308.

**Fix outside repository code:** change the Vercel domain redirect for `www.sulitscan.com` to permanent, then verify representative paths. This cannot be reliably overridden by the current application middleware.

### Low: security hardening

**Evidence:** HSTS, frame, MIME-sniffing, referrer, and permissions headers are present; Content-Security-Policy is not.

**Impact:** security defense-in-depth only, not a direct ranking improvement.

**Recommendation:** introduce CSP in a separate measured release because affiliate destinations, Vercel Analytics, Next.js runtime behavior, and remote images require careful validation.
