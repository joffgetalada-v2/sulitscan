redirect, rendered mobile, structured-data, and representative 404 checks were also healthy.

description set, `/deals` pages 1–8. Those changes are implemented and tested on the branch, but
they are **not live until deployment is complete and production is rechecked**. The sitemap is
expected to move from 261 to 266 URLs after deployment; 266 must not be reported as the live count
until the production sitemap is counted.

The largest commercial risk is outside this documentation change: all 169 public deals were using
reference-price treatment on August 3. Approved partner feeds need refreshing before the current
records expire in late September. AdSense account setup and measurable custom-event reporting also
remain external work.

## Confirmed production strengths

- `robots.txt` and `sitemap.xml` returned 200; robots allows public content, blocks `/api/`, and
  names the canonical sitemap.
- All 261 sitemap URLs returned 200, were indexable, self-canonical, and had one H1. The crawl found
  zero broken, canonical, indexability, title-duplication, or H1 findings.
- HTTP, `www`, and the Vercel hostname redirected permanently to the canonical apex host.
- Sample 404s returned a real 404 with `noindex`.
- Rendered mobile samples had a valid viewport, alternative text, JSON-LD, and no horizontal
  overflow. Observed schema types included Organization, WebSite/SearchAction, BreadcrumbList,
  ItemList, BlogPosting, and FAQPage where appropriate. Continue rendered validation under
  [Google's structured-data policies](https://developers.google.com/search/docs/appearance/structured-data/sd-policies).
- Before this branch, local release gates passed 96 focused Node tests, built 236 routes, passed
  Playwright 85/85 serially, and reported zero production dependency vulnerabilities. These are
  repository checks, not production traffic or performance results.

## AdSense external sequence

1. Create or use the real AdSense account, add `sulitscan.com` under Sites, and obtain its real
   `ca-pub-` ID using [Google's site-connection steps](https://support.google.com/adsense/answer/7584263).
2. Set `NEXT_PUBLIC_ADSENSE_CLIENT_ID` in Vercel for Production, Preview, and Development; keep
   `NEXT_PUBLIC_ADSENSE_ADS_ENABLED` unset or `false`, then redeploy for ownership verification.
3. Confirm the production root contains `google-adsense-account` with that exact ID and `/ads.txt`
   contains the matching `pub-` DIRECT record. Use [Google's ads.txt guidance](https://support.google.com/adsense/answer/12171612).
4. Verify the site and request review in AdSense. Do not claim approval or enable serving while the
   site is pending; approval is not guaranteed.
5. After the account/site is Ready, configure Google's or another certified CMP for required
   regions under the [AdSense CMP requirement](https://support.google.com/adsense/answer/13554116).
6. Enable low-load Auto ads in AdSense, then set `NEXT_PUBLIC_ADSENSE_ADS_ENABLED=true` in Production
   and redeploy. Verify mobile and desktop article pages. Keep ads off deals, categories, stores,
   tools, legal pages, and navigation-only screens.
